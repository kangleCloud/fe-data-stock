## 期初录入与精度

新期初默认填写每股／份成本 `openingUnitCost`，由后端按数量计算总成本。例如数量 `24000`、单位成本 `6.113`，后端返回总成本，页面显示 `146,712.000`。也可切换总成本 `openingCost` 方式；请求只发送当前选中一种，未知成本两者均不传，不按零处理。旧记录单位成本为空时，更正默认沿用原总额方式，不反除单位成本重新解释历史。

全部结构化价格、单位成本、总额、费用、税额、盈亏及百分率固定显示三位小数，HALF_UP，缺失显示 `—`；数量、序号、ID和计数不补小数。列表、详情、预览、公式、图表Tooltip及可访问图表描述采用相同口径。Tooltip读取原始十进制字符串，不从绘图浮点值反取金额。

新价格／单位成本输入有效小数位最多三位（尾零不计，如 `6.11300000` 可接受），金额、费用、税和人工确认净利输入仍最多两位。旧八位价格只在更正且数值未变时原样保留；改价须符合三位规则。不用三位展示值回填表单或参与核算。审计与费用解释 JSON 仍为只读原文，不解析其中历史值作为可操作 ID 或财务字段。

## 事后录入与费用补充

- 主流程填写实际成交价格、数量，成交金额由后端计算。可在补录区域按交割记录覆盖成交金额，存在差异时说明原因。前端不进行财务运算。
- 费用未知可预览并保存，显示“费用待补”，保存 `null`，不默认填零。已知费用时可明确填写实际费用（允许零）、实际结算或人工预估之一，不叠加费用解释明细。
- 可选记录操作前／操作后券商持仓成本价及操作后数量。前值只接受真实券商记录，不以账本平均成本代填；仅操作后信息也可保存观察。数量由后端与业务时点账本校验。
- 买卖及公司行动先预览再保存，修改输入即使预览失效，重新预览后才能保存。预览不入账。写表单使用本人最小 `command-context`（标识、数量、版本），不额外要求持仓页查看权限。
- 保存期间禁止重复提交。超时、网络中断或服务端结果不明时，保留表单并提示先查询流水；读取记录并人工确认未入账后，才允许重新预览再录入。不自动重发 POST，不使用提交键、指纹或声称强幂等。版本冲突需刷新上下文后重新预览。
- 更正采用服务端一次原子替代，保留原始记录、实际费用、人工确认、作废原因及替代关联；不由前端连续请求“作废＋新增”。只读详情无需写权限。

### 券商对账与手动误差控制

所有公式及差额均由后端 BigDecimal 计算，前端展示原始反推、最终采用费用、采用依据和“采用费用与反推值差额”。

| 场景 | 对账公式与条件 |
| --- | --- |
| 买入 | 反推费用＝操作后券商成本总额－操作前券商成本总额－成交金额；实际零仓首次买入允许前总额为零，其他情况缺真实前成本只保留观察 |
| 部分卖出 | 反推费用＝成交金额＋操作后券商成本总额－操作前券商成本总额；摊薄参考收益＝（前成本价－后成本价）×剩余数量 |
| 清仓 | 不依据不存在的操作后成本反推本笔费用；参考毛收益＝（卖出价－前券商成本价）×卖出数量；有选定费用才显示参考净收益 |

反推仅是合计预估，不拆成佣金、税费，也不等同实际扣费。须确认券商成本口径一致、期间无其他变动，并考虑展示舍入误差。原始负差额保留供观察，不能直接采纳，也不自动当零。

用户可明确“采纳反推值为预估费用”，或“手动调整预估费用”。直接采纳使用 `acceptInferredFee=true`；人工修正使用 `estimatedFee`、`acceptInferredFee=false` 并通过现有备注保留调整说明；修改后必须重新预览。后端返回差额 `feeApplied − HALF_UP2(inferredFee)`，不修改原观察。实际费用／结算存在时仍单独对账，不再叠加反推费用。

摊薄参考收益独立于真实账本收益，不累计到已实现盈亏。清仓摊薄参考值可能包含此前卖出影响，不再与此前收益相加。

### 清仓确认与独立现金

清仓默认录入“本轮累计交易净盈亏”（CYCLE），也可明确选择仅本笔（TRADE）。前序交易盈亏未知时，可保留整轮人工确认值，最后一笔无法拆分的 `finalPnl` 显示 `—`，不把前序未知按零倒算。详情同时展示原确认、校准及待复核状态。

本轮交易净盈亏不包含系统另记的分红和补扣税。若券商给出的是综合收益，录入前须核对组成，避免重复计入公司行动。

公司行动不自动核算：待处理记录不入账；一般行动生效须人工明确数量、总成本和现金调整，无变化填零。手工补扣税 `TAX_WITHHOLDING` 输入正税额；生效时指定本人该标的周期、原因和核对依据，后端固定数量／成本变化为零、现金为负，可关联已清仓周期。只补录原到账尚未扣除的税，不重复扣减。待处理税款可暂缺金额和依据。税额独立于交易费用。

## 查询、驾驶舱与数据类型

- 我的持仓默认只展示持有项，支持类型、名称、历史截止及成本／浮盈排序。排序由后端完成后再分页，不在前端局部重排。
- 历史日以上海时间当日末查询，今天查询当前时点，不发送未来截止。行数据、详情及写入口跟随成功加载的查询截止；改变筛选但未查询、查询失败或旧请求迟到时，保留原行及其原截止口径。
- 手工估值、期初和审计整合在持仓详情。估值允许新增、作废、原子替代；历史查询不取截止之后估值，审计只读。
- 完整成本、市值、浮盈或综合收益缺失显示 `—`，不按零补齐。有部分覆盖时单独展示“已覆盖部分”，不替代完整总额。覆盖率为同时具备可靠成本和有效估值的持有标的数量占比。空账本先引导录入。
- 股票／ETF分类、成本环图及收益分项图使用后端聚合，保留可访问表格。预估、待核实、待处理、待复核分别标识；缺值不涂正收益色，也不向图表注入 NaN。固定解释放入可聚焦、可点击 Tips，重要状态和错误仍可见。

金额输入与请求保持十进制字符串，显示使用字符串 HALF_UP 三位舍入，不改写原值。ECharts 只将服务端聚合值转为 Number 绘图，不用于账务；数量仅接受安全整数。

ID 精度处理仅覆盖 `/portfolio/**`：持仓、字典、交易、公司行动、估值、审计及嵌套关联 ID 保持字符串；新增、期初、替代的标量返回同样保持字符串。旧安全 number ID 可归一，已解析的不安全 number ID 必须拒绝并提示重读，不能用 `String(number)` 假装修复。历史审计 JSON 原文只展示，不解析其中数字作为操作 ID。复用统一 request，仅持仓 API 边界校验；分页 total、数量、版本、其他管理 API、登录有效期及公开 GET/SSE 不改变。
