# v1.0.1 个人持仓人工快照

## 当前范围

2026-10-20 起，持仓业务简化为人工录入完整状态、保存历史快照、查看持仓浮动盈亏。仅保留驾驶舱和我的持仓；旧交易记录、费用、公司行动、期初核实、手工单价估值、账本重放、原子更正和截止日查询已退役。三大行情监控页面及 REST/SSE 不受影响。

## 完整状态录入

- 每次明确填写操作后的持仓数量、总市值、总成本、上海快照时点及记录类型；`INITIAL/BUY/SELL/ADJUST` 只是首次录入／买入后／卖出后／调整的说明，不推导成交金额、成本、费用或已实现盈亏。
- 新持仓从现有股票／ETF字典选择；已有持仓沿用身份，标的不可更换。字典选择若命中已有身份，先提示维护已有持仓，再使用该身份和最新版本保存，不重复建立。
- 新增发送 `assetType + dictionaryId`；已有发送 `positionId + expectedVersion`。共同发送 `snapshotAt/operationType/quantity/marketValue/totalCost/remark`，调用 `POST /portfolio/portfolioPosition/saveSnapshot` 一次返回快照字符串ID。无预览、幂等键、客户端财务计算或批量新增。
- 总额为非负十进制字符串，最多两位有效小数；备注最多500字；数量为非负安全整数，时点不可未来。旧八位存储值只无损去掉尾零，真实高精度值不自动舍入，须人工确认后修改。未知金额不得填零或保存为完整状态。
- 清仓时数量、总市值、总成本必须分别明确填零，不自动改用户输入；重新持有复用原身份。
- 旧持仓仅保留原数量和成本供预填，未首次完整保存时展示“待首次完整录入”，市值、时点和盈亏缺失保持未知，不补造历史。
- 保存中禁止重复点击；版本冲突423提示刷新版本、核对输入后明确重存。超时或结果不明不自动重试，并提示关闭表单、先查看历史确认结果。

## 查询与展示

公开接口不变更；私人持仓仅使用原位置的列表／分页／详情／字典、`analysis`、驾驶舱 `summary` 和只读审计API。`analysis` 参数为 `{id}`，返回 `{position,snapshots}`；不再调用旧 `history`、`command-context` 或交易／估值接口。

最新状态由后端给定。平均成本=总成本/数量，参考价格=总市值/数量，浮动盈亏=总市值−总成本，盈亏率=浮动盈亏/总成本×100%；前端不重算。数量0时价格和率未知，成本0时盈亏率未知。所有金融展示固定三位小数、字符串HALF_UP，缺失为 `—`；ID、数量和计数不补小数，零值保留 `0.000`。

驾驶舱标题为“已完整录入持仓汇总”，显示全部身份、有持仓、已完整和待补录数量。金额只汇总已完整记录，零条完整时总额为NULL；待补录不能被误认为资产为零。股票／ETF分类、完整持有市值分布、逐持仓浮动盈亏条图及最新快照表均来自同一次后端summary，不显示已实现收益、分红或旧可靠覆盖率。

详情只画真实人工快照的盈亏折线，按后端 `snapshotAt,id` 顺序原样使用，同秒标识不转Number排序。横轴为人工时点，直线、不平滑、不补点，不套用监控180秒断线规则。单点与清仓零点可见，正红负绿并带金额符号及零轴。Tooltip使用原始十进制字段显示时点、类型、股数、总成本、总市值；完整历史表同源只读。较早补录只进历史，不覆盖最新；录错新增ADJUST，保留旧点。图表沿用BaseChart及ResizeObserver，无轮询、私人SSE或Python调用。

所有持仓ID及嵌套ID保持字符串；旧安全number兼容，不安全number拒绝并提示重读。统一request不变，仅持仓边界归一ID，其他管理接口、行情、金额和分页数量不受影响。审计JSON保持只读原文，不解析其数字为可操作ID。
